# Project

This is a full rewrite of the legacy `spec-exam-pure` React Native app (RN 0.66) as a modern Expo SDK 57 project.

The backend must not be changed.

The legacy repository (`spec-exam-pure`) is a behavioral reference, not a source-code template.

# Stack

- Expo SDK 57
- Expo Router (file-based routing)
- TypeScript strict
- TanStack Query (server state)
- Zustand (client state)
- React Hook Form + Zod (forms)
- Swagger/OpenAPI + Orval (API generation)
- expo-secure-store (tokens)
- @react-native-async-storage/async-storage (non-sensitive persistence)
- No local database (no SQLite, Realm, WatermelonDB)
- Vitest (unit tests)
- Maestro (E2E)

# Architecture

## Route Files
Route files are thin. They must only:
- Read route params
- Set navigation options
- Mount a Screen component from src/features

Never write business logic, API calls, or storage access in route files.

## Feature Layer
Business logic lives in `src/features/<feature-name>`.
Domain types live in `src/entities/<entity>`.
Shared utilities live in `src/shared`.

## State
- Server state: TanStack Query only.
- Client global state: Zustand only.
- Zustand must NOT duplicate Query data.
- sessionStore: auth status, token (memory copy), userId, examTypeId.
- appStore: currentExamProfile, themeMode.

## HTTP Transport
`src/shared/api/client/request.ts` is the Orval mutator.
It must NOT navigate or display UI.
It must NOT modify Zustand directly.
401 calls `sessionStore.getState().handleUnauthorized()`.

## Generated Code
`src/shared/api/generated/` is auto-generated by Orval.
Never edit these files manually.
Generated DTOs must not be used as domain entities.
Convert via adapters: `GeneratedDto → ResponseAdapter → DomainEntity`.

# UI Architecture

- Use NativeWind stable version.
- Do not use NativeWind preview or beta versions.
- Do not introduce a full UI framework without an approved ADR.
- Shared visual primitives belong in `src/shared/components`.
- Feature-specific components belong inside their feature (`src/features/<feature>/components`).
- Route files must not contain substantial UI logic.
- Screens must use semantic design tokens.
- Do not use raw hex colors in screens or feature components.
- Do not invent arbitrary spacing values.
- Use `AppText` instead of raw `Text` for product typography.
- Use `AppButton` instead of creating page-specific buttons.
- Use `AppInput` and `FormField` for forms.
- Use `AppScreen` for top-level screen layout.
- Use `AppDialog` for confirmation flows.
- Inline styles are only allowed for dynamic calculated values.
- Generated pages must include loading, empty, error and success states.
- Every interactive element must have an accessibility label where needed.
- Do not move feature-specific components into shared prematurely.
- Do not expose third-party UI component APIs directly to business screens.

# Persistence Rules

- `expo-secure-store`: access token, user ID (small, sensitive).
- `@react-native-async-storage/async-storage`: exam profile summary, search history, practice snapshot, simulation snapshot, privacy version, theme mode.
- Practice and simulation snapshots must include `schemaVersion: 1`.
- Clear user snapshots on logout and 401.
- No large responses, question lists, or images in AsyncStorage.

# API Rules

- Swagger is the source of truth.
- All endpoints must be generated or explicitly documented as exceptions in `openapi/patches/`.
- Existing request headers must be preserved: `examtoken`, `examTypeId`, `random1`, `random2`, `checkResult`.
- `checkResult` is computed by `FuckingDSign(random1, random2, stringToByte(CHECK_KEY))`.
- Do not invent backend capabilities.
- Do not assume refresh tokens unless confirmed in Swagger.

# Quality Gate

Before completing any task, run:

```bash
pnpm typecheck
pnpm lint
pnpm test
npx expo-doctor
```

All must pass.

# Prohibited

- `any` type (eslint enforces this)
- `fetch` calls directly in screens or route files
- `AsyncStorage` access directly in screens or route files
- Token in plain AsyncStorage
- Business logic in route files
- Unrelated file changes
- Unverified native dependencies
- Silent contract coercion (casting without validation)
- Automatic retry for: payment mutation, order creation, exam submission, withdrawal
