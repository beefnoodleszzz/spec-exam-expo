# spec-exam-expo

## Project Introduction
This is a full rewrite of the legacy `spec-exam-pure` React Native app (RN 0.66) as a modern Expo SDK 57 project. The backend must not be changed. The legacy repository is a behavioral reference, not a source-code template.

## Current Features
- Modern Expo SDK 57 foundation
- NativeWind styling
- TanStack Query for server state
- Zustand for client state
- React Hook Form + Zod for robust form handling
- Orval integration for OpenAPI spec generation

## Missing / Incomplete Features
- VIP / Membership flows (Currently hidden due to incomplete API loops)
- Wallet / Payment features (Hidden)
- Notice / Top Set features (Not supported)
- Complete simulation exam result parsing
- End-to-end device testing (Deferred)

## Tech Stack
- Expo SDK 57
- Expo Router
- TypeScript (Strict)
- TanStack Query
- Zustand
- React Hook Form + Zod
- Swagger/OpenAPI + Orval
- expo-secure-store
- @react-native-async-storage/async-storage
- Vitest
- Maestro (E2E)

## Environment Requirements
- Node.js (>= 18.x recommended)
- pnpm
- iOS Simulator / Android Emulator or physical device

## Installation
```bash
pnpm install
```

## Config
Environment logic is handled in `app.config.ts`. The `APP_VARIANT` variable determines the target configuration (`development`, `production`, `kaozhengtong`).
In `production`, the application requires explicit `API_BASE_URL` and `WEB_BASE_URL` env vars, and completely rejects `localhost` or HTTP urls.

## Run
```bash
pnpm start
# or for specific platforms
pnpm ios
pnpm android
```

## Test
We use Vitest for unit testing.
```bash
pnpm test
```
To run the full validation suite (lint, typecheck, test, expo-doctor):
```bash
pnpm validate
```

## Project Structure
- `src/app/`: Expo Router routes. Thin files that only read params and mount screens.
- `src/features/`: Business logic, categorized by feature.
- `src/entities/`: Domain types.
- `src/shared/`: Shared utilities, UI components, API generation, etc.
- `src/shared/api/generated/`: Auto-generated by Orval. **Do not edit manually.**
- `docs/`: Audits, plans, and architectural documentation.

## Dev Constraints
- `any` type is strictly prohibited.
- `fetch` calls directly in screens or route files are prohibited.
- `AsyncStorage` access directly in screens or route files is prohibited.
- No business logic in route files.
- UI elements must use semantic design tokens and shared primitives (`AppText`, `AppButton`, `AppInput`).

## Security Notes
- Tokens are stored using `expo-secure-store`.
- Plain `AsyncStorage` is only for non-sensitive data (e.g., summaries, theme mode).
- Unverified native dependencies and silent contract coercions are not allowed.

## Device Integration
Device integration testing for iOS Simulator and Android Emulator has been scoped. Currently, the validation of app startup, authentication, navigation, and API connectivity is deferred until all features are fully complete to allow for unified device debugging and testing.
